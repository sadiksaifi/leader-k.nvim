*leader-k.txt*  Inline AI edits and answers                          *leader-k*

==============================================================================
REQUIREMENTS                                        *leader-k-requirements*

  Neovim 0.12+ with LuaJIT  https://neovim.io/
  libcurl shared library   https://curl.se/libcurl/

==============================================================================
USE                                                          *leader-k-use*

Map <leader>k to require("leader-k").open(). In Visual mode it starts on the
selection; in Normal mode, on the current line. Type a request and press
Enter. The model decides how to reply:

  A change      A proposed edit, shown inline as a diff. Accepting applies
                it to the buffer.
  A question    A Markdown answer in a panel on the right. The buffer is
                not changed.

During review: Enter accepts, Backspace rejects, <leader>k follows up, and
<C-c> stops a running request. A changed selection cannot be accepted until
that edit is undone. Errors appear in |:messages|.

While an answer is shown: Backspace closes it and <leader>k follows up.
Focus stays in the code; move into the panel with the usual window commands,
such as <C-w>l. In the panel, q closes the answer and <leader>k follows up.
Closing the panel window also closes the answer. The panel stays open
through follow-ups that propose edits, until the session ends.

Follow-ups continue one conversation and can switch between edits and
answers. Enter alone on a follow-up regenerates the last reply. After you
accept a proposal, starting again on the same lines, or in Normal mode on a
line inside them, continues the conversation for two minutes.

A characterwise or blockwise selection (|v| or |CTRL-V|) sends the lines it
touches plus the selected characters. Only those characters are
highlighted. An edit still replaces whole lines.

To force one kind of reply, pass a mode: >lua
    require("leader-k").open({ mode = "edit" }) -- always propose an edit
    require("leader-k").open({ mode = "ask" })  -- always answer
<
In a buffer that is not 'modifiable', the default mode only answers.

                                                            *:LeaderK*
:[range]LeaderK [request]
    Start on the range (default: current line); the model decides how to
    reply. A request skips the prompt.

                                                        *:LeaderKEdit*
:[range]LeaderKEdit [instruction]
    Like |:LeaderK|, but always proposes an edit.

                                                         *:LeaderKAsk*
:[range]LeaderKAsk [question]
    Like |:LeaderK|, but always answers.

SETUP                                                      *leader-k-setup*

>lua
    ---@type leader_k.Config
    local opts = {
      base_url = "https://openrouter.ai/api/v1", -- Required API root.
      model = "openai/gpt-6-luna",             -- Required model ID.
      api_key = { env = "OPENROUTER_API_KEY" },   -- Optional key source.
      params = { -- Optional; omit to use the model's default.
        -- "none" (off), "low", "medium", "high", "xhigh", "max"
        reasoning = { effort = "none" },
      },
    }
    require("leader-k").setup(opts)
<
leader-k uses OpenAI-compatible streaming Chat Completions. Plain http://
works on localhost, 127.0.0.1, or [::1].

Official endpoint documentation:
  OpenRouter  https://openrouter.ai/docs/quickstart
  OpenAI     https://developers.openai.com/api/reference/resources/chat
  Anthropic  https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk
  Groq       https://console.groq.com/docs/openai
  Ollama     https://docs.ollama.com/api/openai-compatibility
  llama.cpp  https://github.com/ggml-org/llama.cpp/tree/master/tools/server

`api_key` is optional: use a literal string or { env = "NAME" }. Environment
references are resolved on each request from Neovim's environment. For
keyless endpoints, leave `api_key` unset. Authentication errors appear in
|:messages|.

Optional fields:
  params          Extra Chat Completions request fields. Check model support.
                  Leave `model` and `messages` to the plugin; streaming stays
                  enabled. A truncated response is rejected.
  context_bytes   Context sent on each side of the selection. Default 50000.
  timeout_ms      Request limit. Default 180000.
  libcurl         Path to libcurl if automatic loading fails.
  keys            Review key mappings; see |leader-k-keys|.

Run |:checkhealth| leader-k to inspect your setup.

==============================================================================
KEYS                                                        *leader-k-keys*

  keys.accept  <CR>       Apply the proposal.
  keys.reject  <BS>       Discard the proposal or stop a request.
  keys.cancel  <C-c>      Stop a request. A refine returns to its proposal.
  keys.refine  <leader>k  Follow up on a proposal or answer; empty input
                          regenerates the last reply.

Outside their session, or off screen, the keys keep their usual meaning.

In the prompt: Enter sends; Up/Down recall requests; <C-c> cancels.
Esc enters Normal mode, where Esc or q cancels.

In the answer panel: q closes the answer, keys.refine follows up, and
keys.cancel stops a running request.

==============================================================================
TRANSPORT                                               *leader-k-transport*

Requests run through libcurl in-process. TLS is verified and redirects are
not followed. If configured, the key is sent as a Bearer token and is not
logged. A literal key remains in your config file. Each request includes
the selected lines, the selected characters of a characterwise selection,
surrounding code (up to `context_bytes` on each side), file metadata,
diagnostics on the selection, and the earlier requests and replies of the
conversation.

LIMITS                                                     *leader-k-limits*

Edits replace whole lines. One session runs per buffer; sessions in other
buffers can run in parallel. Request context comes from the current file.
Tree-sitter syntax colors on proposed lines require a parser for the
filetype. Answers use the bundled Markdown parser; colors in their code
blocks require a parser for the block's language.

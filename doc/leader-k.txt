*leader-k.txt*  Inline AI edits and answers                          *leader-k*

==============================================================================
REQUIREMENTS                                        *leader-k-requirements*

  Neovim 0.12+ with LuaJIT  https://neovim.io/
  libcurl shared library   https://curl.se/libcurl/

==============================================================================
USE                                                          *leader-k-use*

Map <leader>k to require("leader-k").open(). In Visual mode it starts on the
selection; in Normal mode, on the current line. A panel opens on the right
of the editor with the selection attached and an input for your request.
Type a request and press Enter. The model decides how to reply:

  A change      A proposed edit, shown inline as a diff. Accepting applies
                it to the buffer.
  A question    A Markdown answer in the panel. The buffer is not changed.

The panel holds the conversation. Its transcript sits above the input. A
dim divider above the input shows the status, such as "+3 -3 Review it in
the code.", and the last row of the input box shows the keys. The code keeps the
selection marked and shows a diff when a reply proposes an edit; focus
then moves to the code for review.

During review: Enter accepts, Backspace rejects, <leader>k moves into the
panel input to refine, and <C-c> stops a running request. These keys work
in the code; the last row of the input box lists them while the input is
not focused. A changed
selection cannot be accepted until that edit is undone. Errors appear in
|:messages|.

Accepting or rejecting a proposal ends the conversation, and so do q in the
panel and closing either panel window. Backspace in the code also closes an
answer. One conversation runs at a time.

Follow-ups continue the conversation and can switch between edits and
answers. Enter alone on a follow-up regenerates the last reply. After you
accept a proposal, starting again on the same lines, or in Normal mode on a
line inside them, continues the conversation for two minutes.

During a conversation, <leader>k in Visual mode attaches the selection, in
any buffer, to the next message. The input names it above the text, for
example "Attached: lines 3-9 of sample.lua", and the transcript keeps that
line with the message. From then on, edits replace that selection. A
selection made before the first request replaces the first one. In Normal
mode, <leader>k only moves into the input.

A characterwise or blockwise selection (|v| or |CTRL-V|) sends the lines it
touches plus the selected characters. Only those characters are
highlighted. An edit still replaces whole lines.

To force one kind of reply, pass a mode: >lua
    require("leader-k").open({ mode = "edit" }) -- always propose an edit
    require("leader-k").open({ mode = "ask" })  -- always answer
<
In a buffer that is not 'modifiable', the default mode only answers. A
conversation keeps the mode it started with.

                                                            *:LeaderK*
:[range]LeaderK [request]
    Start on the range (default: current line); the model decides how to
    reply. A request is sent at once. During a conversation, the range is
    attached to the next message instead.

                                                        *:LeaderKEdit*
:[range]LeaderKEdit [instruction]
    Like |:LeaderK|, but always proposes an edit.

                                                         *:LeaderKAsk*
:[range]LeaderKAsk [question]
    Like |:LeaderK|, but always answers.

==============================================================================
SETUP                                                      *leader-k-setup*

>lua
    ---@type leader_k.Config
    local opts = {
      base_url = "https://openrouter.ai/api/v1", -- Required API root.
      model = "openai/gpt-6-luna",             -- Required model ID.
      api_key = { env = "OPENROUTER_API_KEY" },   -- Optional key source.
      params = { -- Optional; omit to use the model's default.
        -- "none" (off), "low", "medium", "high", "xhigh", "max"
        reasoning = { effort = "none" },
      },
    }
    require("leader-k").setup(opts)
<
leader-k uses OpenAI-compatible streaming Chat Completions. Plain http://
works on localhost, 127.0.0.1, or [::1].

Official endpoint documentation:
  OpenRouter  https://openrouter.ai/docs/quickstart
  OpenAI     https://developers.openai.com/api/reference/resources/chat
  Anthropic  https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk
  Groq       https://console.groq.com/docs/openai
  Ollama     https://docs.ollama.com/api/openai-compatibility
  llama.cpp  https://github.com/ggml-org/llama.cpp/tree/master/tools/server

`api_key` is optional: use a literal string or { env = "NAME" }. Environment
references are resolved on each request from Neovim's environment. For
keyless endpoints, leave `api_key` unset. Authentication errors appear in
|:messages|.

Optional fields:
  params          Extra Chat Completions request fields. Check model support.
                  Leave `model` and `messages` to the plugin; streaming stays
                  enabled. A truncated response is rejected.
  context_bytes   Context sent on each side of the selection. Default 50000.
  timeout_ms      Request limit. Default 180000.
  libcurl         Path to libcurl if automatic loading fails.
  keys            Review key mappings; see |leader-k-keys|.

Run |:checkhealth| leader-k to inspect your setup.

==============================================================================
KEYS                                                        *leader-k-keys*

  keys.accept  <CR>       Apply the proposal.
  keys.reject  <BS>       Discard the proposal or stop a request.
  keys.cancel  <C-c>      Stop a request. A refine returns to its proposal.
  keys.refine  <leader>k  Move into the panel input to follow up on a
                          proposal or answer.

Outside their session, or off screen, the keys keep their usual meaning.

In the panel transcript: q ends the conversation; keys.refine, i, or a
moves into the input; keys.cancel stops a running request.

In the panel input: Enter sends, and Enter alone on a follow-up regenerates
the last reply; Up/Down recall requests; keys.cancel stops a running
request or returns to the code. Esc on an empty input cancels a new
conversation, or else returns to the code; with text, it enters Normal
mode, where Esc returns to the code and q ends the conversation.

==============================================================================
TRANSPORT                                               *leader-k-transport*

Requests run through libcurl in-process. TLS is verified and redirects are
not followed. If configured, the key is sent as a Bearer token and is not
logged. A literal key remains in your config file. Each request includes
the selected lines, the selected characters of a characterwise selection,
surrounding code (up to `context_bytes` on each side), file metadata,
diagnostics on the selection, and the earlier requests and replies of the
conversation. A selection attached to a follow-up adds its lines; one in a
file the conversation has not used yet also adds that file's surrounding
code and metadata.

==============================================================================
HIGHLIGHTS                                             *leader-k-highlights*

  LeaderKAdd  LeaderKAddText  LeaderKDelete  LeaderKDeleteText
  LeaderKSelection  LeaderKPending  LeaderKBar  LeaderKBarDelete
  LeaderKSpinner  LeaderKKey  LeaderKHint
  LeaderKCountAdd  LeaderKCountDelete  LeaderKWarn
  LeaderKPlaceholder  LeaderKFlash  LeaderKFocus

In the panel, your messages use the color of LeaderKUserBar for the bar on
their left and LeaderKUser for their background. LeaderKUserBar links to
Function. LeaderKUser blends the background of Normal with the color of
LeaderKUserBar at 20%, or links to CursorLine when either color is missing.
Notes such as "Proposed an edit." and attached selections use LeaderKNote.
The divider above the input uses LeaderKDivider, the color of NonText on
the background of Normal. A selection attached to the next message is
highlighted with LeaderKSelection.

==============================================================================
LIMITS                                                     *leader-k-limits*

Edits replace whole lines. One conversation runs at a time. Request
context comes from the files of the attached selections. Tree-sitter
syntax colors on proposed lines require a parser for the filetype. Answers
use the bundled Markdown parser; colors in their code blocks require a
parser for the block's language.

*leader-k.txt*  AI chat sidebar with reviewed edits                 *leader-k*

==============================================================================
REQUIREMENTS                                        *leader-k-requirements*

  Neovim 0.12+ with LuaJIT  https://neovim.io/
  libcurl shared library    https://curl.se/libcurl/
  git and rg (optional)     Used by the list_files and search tools.

==============================================================================
USE                                                          *leader-k-use*

Map <leader>k to require("leader-k").open() in Normal mode. It opens the
sidebar and moves into its input. Type a request and press Enter. With
nothing attached, the first message sends the current file.

While the sidebar is open, select code in any buffer. A hint above the
selection names keys.attach, <leader>k by default. Press it to attach the
selection to the next message; the cursor stays in the code. Repeat it to
collect several selections. `@path` in a message attaches that project
file. The attachments show above the input until they are sent.

The model works in the project root: the nearest directory above the file
that holds one of `root_markers`, or the current directory. It can read,
list, search, edit, and create files there. It cannot touch files outside
the root, inside .git, or ignored by git, and it cannot delete files or run
commands.

Edits are proposals. When a reply proposes edits, the first changed file
opens in the code window with the edit shown inline, and the transcript
lists every changed file. A hint in the bottom right corner of the code
window names the review keys. Accepting writes the edit into the buffer,
as one undo step, without saving it. A file edited after the proposal
cannot be accepted; reject it or ask again. The next message tells the
model which files were accepted and rejected.

Closing the sidebar window keeps the conversation; <leader>k reopens it.
Closing it also pauses the review, and reopening it resumes the review.
`q` in the sidebar ends the conversation. With edits pending, it asks for a
second `q`. Errors appear in the transcript and in |:messages|.

                                                            *:LeaderK*
:[range]LeaderK [request]
    Open the sidebar. With a range, attach those lines. With a request,
    send it.

                                                         *:LeaderKAdd*
:LeaderKAdd [path]
    Attach a whole file, the current buffer's by default.

                                                         *:LeaderKNew*
:LeaderKNew
    Start a new conversation. Pending edits are discarded.

SETUP                                                      *leader-k-setup*

>lua
    ---@type leader_k.Config
    local opts = {
      base_url = "https://openrouter.ai/api/v1", -- Required API root.
      model = "openai/gpt-6-luna",             -- Required model ID.
      api_key = { env = "OPENROUTER_API_KEY" },   -- Optional key source.
      params = { -- Optional; omit to use the model's default.
        -- "none" (off), "low", "medium", "high", "xhigh", "max"
        reasoning = { effort = "none" },
      },
    }
    require("leader-k").setup(opts)
<
leader-k uses OpenAI-compatible streaming Chat Completions with tool calls.
The model must support tool calls. Plain http:// works on localhost,
127.0.0.1, or [::1].

Official endpoint documentation:
  OpenRouter  https://openrouter.ai/docs/quickstart
  OpenAI     https://developers.openai.com/api/reference/resources/chat
  Anthropic  https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk
  Groq       https://console.groq.com/docs/openai
  Ollama     https://docs.ollama.com/api/openai-compatibility
  llama.cpp  https://github.com/ggml-org/llama.cpp/tree/master/tools/server

`api_key` is optional: use a literal string or { env = "NAME" }. Environment
references are resolved on each request from Neovim's environment. For
keyless endpoints, leave `api_key` unset.

Optional fields:
  params          Extra Chat Completions request fields. Check model support.
                  Leave `model`, `messages`, and `tools` to the plugin;
                  streaming stays enabled.
  max_read_bytes  Most bytes one file read or attached file sends.
                  Default 100000.
  max_steps       Most requests for one message. Default 25.
  root_markers    Names that mark the project root. Default { ".git" }.
  timeout_ms      Limit for each request. Default 180000.
  libcurl         Path to libcurl if automatic loading fails.
  keys            Key mappings; see |leader-k-keys|.

Run |:checkhealth| leader-k to inspect your setup.

KEYS                                                        *leader-k-keys*

While a file is under review, in its buffer:
  keys.accept      <CR>   Accept the file.
  keys.reject      <BS>   Reject the file.
  keys.next_file   ]f     Review the next changed file.
  keys.prev_file   [f     Review the previous changed file.
  keys.next_hunk   ]c     Go to the next change in the file.
  keys.prev_hunk   [c     Go to the previous change in the file.

These keys act only while the file is under review and the sidebar is
open. Elsewhere they keep their usual meaning, including your own mappings.

In Visual mode, while the sidebar is open:
  keys.attach      <leader>k   Attach the selection.

The attach key replaces a global Visual-mode mapping of the same key only
while the sidebar is open, and restores it when the sidebar closes.

In the transcript:
  <CR>             Review the changed file under the cursor.
  keys.accept_all  A      Accept every pending file.
  keys.reject_all  R      Reject every pending file.
  keys.refine      <leader>k, i, a   Move into the input.

In the sidebar:
  keys.cancel      <C-c>  Stop the reply.
  q                       Close the sidebar and end the conversation.

In the input: Enter sends; Up/Down recall messages. With the input empty,
Esc returns to the code and Backspace removes the newest attachment.

==============================================================================
TRANSPORT                                               *leader-k-transport*

Requests run through libcurl in-process. TLS is verified and redirects are
not followed. If configured, the key is sent as a Bearer token and is not
logged. A literal key remains in your config file.

Each request sends the conversation so far: your messages, the attached
code with its diagnostics, the model's replies, and the tool results,
which include the contents of every file the model read. list_files and
search run git ls-files, rg, or git grep in the project root.

LIMITS                                                     *leader-k-limits*

One conversation runs at a time. Edits replace exact text, so the model
must read a file before it edits it. Tree-sitter colors on proposed lines
require a parser for the filetype.
